# ADR 0001：AI 服务选型与流式输出方案

- 状态：**已被 [ADR 0002](./0002-默认供应商改为智谱免费模型.md) 取代**（原结论中的选型理由仍成立，只是默认供应商换成了免费方案）
- 日期：2026-10-02
- 取代日期：2026-10-02

## 背景

项目需要调用大模型做英语陪练与批改，要求：中文语境可用、成本低、能流式输出、方便后续换模型。

## 选项

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| OpenAI 官方 API | 生态最成熟、文档全 | 国内访问不稳定，需外币支付 |
| DeepSeek（OpenAI 兼容） | 国内直连、价格低、接口与 OpenAI 一致 | 模型能力略弱于 GPT 系列 |
| WorkBuddy 托管后端 / 其他 BaaS | 免密钥管理 | 绑定平台，不利于开源展示 |

## 结论

选择 **DeepSeek**，通过 OpenAI 兼容格式调用（`https://api.deepseek.com/chat/completions`），原因：

1. 接口与 OpenAI 一致，将来换模型只需改 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_API_KEY`
2. 国内可直连，开发与演示不受网络影响
3. 成本足够低，学生项目能长期跑

流式输出采用 **SSE + JSON Lines**：

- 对话场景：逐字推送 `delta`，用户看到打字效果
- 纠错场景：每行一个 JSON 对象（JSON Lines），来一行渲染一条，兼顾"边生成边看到"和结构化结果

## 影响

- 所有 AI 调用集中在 `lib/api/ai.ts`（原名 `deepseek.ts`），换模型只改这一处
- 前端不接触任何密钥，只调 `/api/chat` 与 `/api/correct`
